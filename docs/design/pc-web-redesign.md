# PC Web 重构设计方案

## 目标

将当前按功能分别拼装的页面，重构为面向企业知识管理的统一 PC 工作台。首期聚焦用户每天最常用的三件事：进入知识空间、管理空间内文档、基于授权资料进行问答。

本方案不改变既有的权限、文档、检索或 Agent 后端模型；只重组 Web 的信息架构、页面层级、组件和视觉规范。

## 已确认的产品决策

- 定位：专业、克制的企业后台，不做消费级聊天产品。
- 终端：PC 优先，以 `1440px` 为主要设计宽度，`1280px` 为最低完整可用宽度；首期不为移动端设计独立交互。
- 样式：蓝白为主，浅灰背景、白色内容表面、深蓝强调色；少用渐变、装饰图形和多余卡片。
- 技术：`Tailwind CSS v4`、`shadcn/ui` 和 `Lucide` 图标；新页面不再继续扩展全局手写样式。
- 工作台：首期仅展示可访问空间数、文档总数、处理中任务；为后续趋势图和质量指标预留区域，不展示最近空间或最近会话。
- 上传：只在知识空间的文档页提供，工作台不提供上传入口。
- 问答范围：新建会话默认选择全部可访问空间；用户可在问答页按需取消或缩小范围。

## 领域边界

知识空间是权限、文档、检索和引用的共同边界。每份逻辑文档只属于一个知识空间；跨空间导入同一文件也必须形成独立的文档和 ACL。因此，文档列表和上传始终位于特定空间内，工作台只做汇总，不提供无上下文的全局上传。

多空间问答仍遵循现有的最严格策略交集，界面不能把“全部可访问空间”误导为忽略出网或模型能力限制。

## 信息架构

### 全局主导航

1. **工作台**：统计概览与后续分析入口。
2. **知识空间**：可访问空间的目录；进入后管理该空间资料和权限。
3. **智能问答**：会话列表、问答、知识范围和引用。

个人信息与系统管理放入右上角账户菜单；仅系统管理员可见系统管理。

### 知识空间内导航

空间页使用横向页签，不使用第二个永久侧栏：

- 空间概览：文档总数、就绪数、处理中任务和后续空间级图表。
- 文档：上传、网页导入、筛选、列表和文档详情。
- 成员与权限：仅空间管理员可见。

检索测试、重新索引和 Chunk 查看属于管理与调试能力：Chunk 位于文档详情；检索测试收纳在空间管理入口，不进入全局主导航。

## 权限与可见性

| 用户类型 | 主要可见能力 |
| --- | --- |
| 普通用户 | 工作台、已授权空间、文档查看与搜索、智能问答、引用查看 |
| 空间管理员 | 普通用户能力，加上传/网页导入、替换/删除、成员权限、处理状态、Chunk、重新索引和检索测试 |
| 系统管理员 | 空间管理员能力，加空间创建和平台级设置 |

界面只隐藏无权限操作以降低噪声；服务端仍是所有权限判断的唯一来源。

## 核心页面

### 工作台

- 页面标题与简短说明。
- 三个统计卡：可访问知识空间、文档总数、处理中任务。
- 固定一块“分析与趋势”扩展区域，待后端统计接口与真实数据就绪后再加入图表。
- 不放上传按钮、最近会话或最近空间。

### 知识空间概览

- 面包屑、空间名称、描述和空间设置入口。
- 横向页签：概览、文档、成员与权限。
- 三个空间级统计卡：文档总数、已就绪文档、处理中任务。
- 文档处理状态分布；后续可扩展为质量、索引和检索统计。

### 文档列表

- 上传文档为唯一高强调主操作；网页导入为次要操作。
- 首屏筛选：关键词（名称、内容、上传人）、文档类型、处理状态、更新时间。
- “更多筛选”容纳标签、来源、权限范围等低频条件。
- 表格显示名称与类型、来源、处理状态、更新时间和更多操作。
- 文档详情保留内容预览、版本历史、Chunk 列表、下载、替换、删除及管理员重新索引入口。

### 智能问答

- 左侧为会话列表和新建对话；右侧为当前问答内容。
- 顶部显示可点击的知识范围，默认“全部可访问空间”。
- 范围面板支持搜索、复选、全选和清空；多选时显示数量而不是罗列所有空间名。
- 回答下方统一显示引用卡片，包含文档名、格式和原文位置；点击后沿现有 API 重新鉴权。
- 发送区固定在答案区底部，清楚显示加载、取消和错误状态。

## 组件与视觉规范

- 使用 `shadcn/ui` 作为按钮、输入框、选择器、表格、弹窗、下拉菜单、页签和提示组件的基础。
- 业务组件只组合基础组件，不复制一份新的按钮、表格或弹窗样式。
- 建立统一 token：页面背景、表面、边框、正文/次级文字、主色、成功/警告/失败状态。
- 表格和信息密集页优先可扫描性：弱分隔线、稳定列宽、状态标签和可点击行。
- 不在首期增加复杂动效；仅保留加载、下拉与面板的简短反馈。

## 社区借鉴原则

- 借鉴 RAGFlow 把解析、Chunk 和检索测试放进知识库管理链路的做法，而非将调试工具暴露为主功能。
- 借鉴 AnythingLLM 的工作区问答与来源引用体验，让问答和资料范围保持直接关联。
- 借鉴 Dify 将文档组织进知识库的心智模型，但继续使用本项目已有的“知识空间 + ACL”术语和权限约束。

参考：<https://ragflow.net/docs/configure_knowledge_base>、<https://github.com/Mintplex-Labs/anything-llm>、<https://docs.dify.ai/guides/knowledge-base/retrieval>。

## 实施顺序

1. 引入 Tailwind、shadcn/ui 和 Lucide，建立主题 token、应用壳和 PC 布局。
2. 实现工作台与知识空间目录，首页从直接跳转问答改为工作台。
3. 重构空间概览、文档列表和文档详情，接入现有上传、导入、版本、Chunk 与搜索能力。
4. 重构智能问答页，保留现有流式协议，加入默认全选和多空间范围面板。
5. 将检索测试、重新索引和评测入口以管理员工具形式接入空间，不增加一级导航。
6. 使用真实数据进行 PC 端走查、权限回归和视觉一致性检查。

## 非目标

- 本轮不改变服务端权限模型、检索算法、Agent 协议或评测门槛。
- 本轮不实现移动端专用布局。
- 本轮不提前实现没有真实数据支持的复杂仪表盘。
