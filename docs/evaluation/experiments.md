# 实验日志

实验按编号顺序追加，旧记录不删除。每次尽量只改一个主要因素，这样才能看清“什么改动带来了什么变化”。

## 记录模板

### E000 — 日期 — 简短名称

- **对比对象**：例如 E001；首次基线写“无”。
- **目标与假设**：想解决什么问题，为什么认为这次改动有效。
- **改动**：具体改了什么。
- **条件**：数据集、代码提交、运行方式。
- **结果**：`Recall@10: 旧值 -> 新值`；`nDCG@10: 旧值 -> 新值`；漏检题变化。
- **结论与下一步**：保留、回退或继续验证，以及下一件事。

## E001 — 2026-07-26 — SciFact 初始基线

- **对比对象**：无；首次基线。
- **目标与假设**：不改现有检索配置，先得到后续优化可比较的起点分数。
- **改动**：无；使用当前 embedding、词法检索、RRF 和 reranker 配置。
- **条件**：D001 SciFact 固定 50 题 / 200 篇论文；代码提交 `b74f233`；真实端到端检索，不调用回答生成模型。
- **结果**：`Recall@10: - -> 0.6133`；`nDCG@10: - -> 0.4236`；50 题中 19 题未在前 10 条结果命中任何相关论文。
- **结论与下一步**：未达到门槛，保留为基线。E002 先分析漏检题，再只调整一个主要因素（建议从混合检索权重或候选数量开始）并用同一 D001 子集复测。

## E002 — 2026-07-26 — 扩大 rerank 候选数

- **对比对象**：E001。
- **目标与假设**：减少同一论文多个文本块挤占前 10 名额的问题；将 rerank 输出从 10 个文本块提高到 30 个，再按论文去重取前 10。
- **改动**：仅设置 `RETRIEVAL_RERANK_TOP_K=30`，评测请求返回最多 30 个文本块；其余配置不变。
- **条件**：D001 SciFact 固定 50 题 / 200 篇论文；代码提交 `b74f233`；真实端到端检索。
- **结果**：`Recall@10: 0.6133 -> 0.6133`；`nDCG@10: 0.4236 -> 0.4236`；漏检题数无变化。
- **结论与下一步**：无效，不保留该配置。E003 应单独验证 mock reranker 是否拖累排序；保持候选数量和评测集不变。

## E003 — 2026-07-26 — 关闭 mock reranker

- **对比对象**：E001。
- **目标与假设**：当前 reranker 是简单 mock 实现，可能无法理解英文科学语义并把较好的融合结果排坏。
- **改动**：仅在隔离评测空间临时关闭 `rerankerEnabled`；评测完成后已恢复原设置。
- **条件**：D001 SciFact 固定 50 题 / 200 篇论文；代码提交 `b74f233`；其余检索参数与 E001 相同。
- **结果**：`Recall@10: 0.6133 -> 0.8200`；`nDCG@10: 0.4236 -> 0.7597`；`nDCG@10` 已达到门槛，Recall@10 距离门槛仍差 `0.03`。
- **结论与下一步**：有效。不要在英文科学检索空间启用 mock reranker；后续应接入真实 reranker，或保持关闭。E004 仅增加基础召回候选数，验证能否补足剩余 Recall 差距。

## E004 — 2026-07-26 — 扩大基础召回候选数

- **对比对象**：E003。
- **目标与假设**：将向量和词法两路召回候选数从 50 增加到 100，可能让更多相关文本块进入 RRF 融合阶段，从而提升最终前 10 的召回。
- **改动**：仅设置 `RETRIEVAL_VECTOR_TOP_K=100` 和 `RETRIEVAL_LEXICAL_TOP_K=100`；reranker 保持关闭，其余参数不变。
- **条件**：D001 SciFact 固定 50 题 / 200 篇论文；代码提交 `b74f233`；真实端到端检索。
- **结果**：`Recall@10: 0.8200 -> 0.8200`；`nDCG@10: 0.7597 -> 0.7597`；漏检题数无变化。
- **结论与下一步**：无效，不保留该配置。E005 应只调整 RRF 融合参数，验证两路结果的融合方式是否是剩余漏检的原因。

## E005 — 2026-07-26 — SciFact 引用相关性基线

- **对比对象**：无；这是引用评测的第一份基线，不与 E001-E004 的纯检索指标直接比较。
- **目标与假设**：验证真实 Agent 是否能输出结构化 citation 事件，并量化这些引用是否指向 SciFact 标注相关论文。
- **改动**：新增 `run_scifact_citations.py`，调用 `/v1/agent/runs`、收集 citation 事件并映射回 SciFact 论文 ID；不修改运行时检索配置。
- **条件**：D001 SciFact 固定 50 题 / 200 篇论文；使用当前评测空间的正常配置；真实 Agent 问答链路。
- **结果**：`Citation precision: - -> 0.1207`；全部 50 题均收到 citation 事件。报告中的 `Recall@10 = 0.5367`、`nDCG@10 = 0.3981` 基于“最终引用列表”，不应与纯检索实验横向比较。
- **结论与下一步**：引用采集与自动评分链路已完成，但 SciFact 只能验证引用是否指向相关论文，不能判断每句回答是否被充分支持。下一步接入带 supporting facts 的 HotpotQA 或人工标注样本，形成真正的引用准确率出口证据。

## E006 — 2026-07-27 — HotpotQA 文档级证据引用基线

- **对比对象**：E005；数据集从“相关论文”升级为带 supporting facts 的 HotpotQA。
- **目标与假设**：确认真实 Agent 输出的引用是否指向回答该题所需的标准证据文章。
- **改动**：从 Hugging Face 的 `hotpotqa/hotpot_qa` `distractor/validation` 配置提取固定 20 题和 199 篇候选文章；导入隔离空间后执行真实 Agent 问答和 citation 采集。
- **条件**：D002 HotpotQA 固定 20 题 / 199 篇文章；正常评测配置；不改变运行时检索或生成参数。
- **结果**：`Citation precision: - -> 0.7833`；20 题均收到 citation 事件。引用列表的 `Recall@10 = 0.6000`、`nDCG@10 = 0.6526` 仅用于描述最终引用列表，不能与 E001-E004 的纯检索结果横向比较。当前 `0.7833` 未达到引用门槛 `0.95`。
- **结论与下一步**：已经具备文档级证据引用出口检查。HotpotQA 的 supporting facts 同时标有句子位置，但当前评分只比较文章标题；后续补充句子级映射或人工抽检后，才能判断回答中的每个表述是否被引用充分支持。
